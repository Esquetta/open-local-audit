# v0.10.0 Plan: Google Places Website Resolver

Status: planned
Target: next version after `v0.9.0`
Implementation status: not started

## Release goal

Add an opt-in Google Places provider to the existing `discover` command so operators can identify local lead candidates and determine which businesses have official website URLs before running Open Local Audit.

## Planned user-facing command

```bash
open-local-audit discover "guzellik salonu Umraniye" \
  --provider google-places \
  --profile beauty \
  --out-dir reports/umraniye-beauty \
  --export-csv leads.csv
```

## Planned scope

- Add `google-places` provider option.
- Read `GOOGLE_MAPS_API_KEY` from the environment.
- Call official Google Places Text Search API.
- Request only the fields needed for discovery, especially `id`, `displayName`, and `websiteUri`.
- Resolve `websiteUri` into existing discovery rows.
- Audit website-present candidates through the existing audit pipeline.
- Export all candidates to `leads.csv`, including website-missing rows.
- Keep `manual-csv` provider working unchanged.

## Explicit non-goals

- No Google Maps browser scraping.
- No reviews, photos, ratings, or broad profile collection.
- No Google Business Profile automation.
- No email or WhatsApp outreach sending.
- No CRM database.
- No long-term raw Places data cache.

## Data handling rules

Default output may include:

- provider source,
- source ID or place ID,
- label where needed for operator triage,
- website presence,
- website URL,
- audit status,
- audit score,
- top finding,
- priority,
- next action,
- report path.

Default output must not include:

- raw Google Places API response,
- review text,
- photos,
- rating details,
- business phone/address fields unless explicitly approved in a later design.

## Required tests

- API key missing behavior.
- Google provider request uses field masks.
- Mocked response with `websiteUri` creates a website-present candidate.
- Mocked response without `websiteUri` creates a website-missing candidate.
- Website-present candidate is audited when not in dry-run mode.
- `--dry-run` skips audits but still writes discovery CSV.
- Manual CSV provider behavior remains unchanged.
