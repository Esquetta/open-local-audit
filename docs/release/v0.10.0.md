# Open Local Audit v0.10.0

## Highlights

- Added `discover "<query>" --provider google-places` for opt-in Google Places Text Search discovery.
- Added `GOOGLE_MAPS_API_KEY` support with a clear missing-key error.
- Requested a strict Google Places field mask: `places.id`, `places.displayName`, and `places.websiteUri`.
- Mapped Google Places candidates into the existing discovery pipeline and `leads.csv` export.
- Reused the existing audit pipeline for website-present Google candidates.
- Kept website-missing Google candidates in prospect output with `hasWebsite=no`.

## Verification

Run before tagging and publishing:

```bash
npm run release-check
npm pack
npx --yes --package ./open-local-audit-0.10.0.tgz open-local-audit --help
```

Run after publishing:

```bash
npm view open-local-audit@0.10.0 version dist.tarball bin
npx --yes open-local-audit@0.10.0 discover --help
```

## Known Limits

- `google-places` requires `GOOGLE_MAPS_API_KEY`; discovery fails fast if the key is missing, and usage can incur Google Maps Platform billing.
- CI tests use mocked Google responses only.
- The provider does not scrape Google Maps, collect reviews/photos/ratings, send outreach, or store raw Places responses.
- Web UI, branded PDF reports, Lighthouse integration, and broader profile packs remain deferred.
